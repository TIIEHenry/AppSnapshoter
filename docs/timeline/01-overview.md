# 背景与目标

[← 返回索引](../TIMELINE_FEATURE.md)

> 版本：v1.1 · 日期：2026-06-11 · 状态：待评审

---

## 1.1 背景

当前首页底部导航有两个 Tab：

| Tab | Fragment | 职责 |
|-----|----------|------|
| 存档 | `LauncherFragment` | 按分组展示应用及其快照列表 |
| 应用 | `AppsFragment` | 展示已安装应用，用于添加/管理 |

用户查看和操作快照必须逐组、逐应用展开，无法按时间维度跨分组检索。当需要「找出某段时间内所有备份过的应用并批量恢复/清理」时，操作路径长、效率低。

## 1.2 目标

在首页底部导航新增 **时间线** Tab，实现：

1. 按时间区域筛选备份快照
2. 列表展示该时间区域内**有快照的应用**（跨分组）
3. 支持多选、全选
4. 支持批量 **恢复**、**删除**
5. 当某应用在时间区域内有多个快照时，批量恢复前让用户选择策略：**新快照优先** 或 **旧快照优先**

## 1.3 非目标（首版不做）

- 时间线图表/日历视图
- 批量导出
- 按快照粒度逐条展示与操作（首版以应用为粒度）
- 高级恢复（选择数据类型）
- 跨设备同步

## 1.4 已定设计决策

| 决策 | 结论 | 理由 |
|------|------|------|
| Tab 顺序 | `存档 \| 时间线 \| 应用` | 存档仍是主入口，时间线为辅助视图 |
| 列表粒度 | `(groupId, packageName, userId)` 一行，不跨组合并 | 保留分组上下文，避免误操作 |
| 删除语义 | 删除时间区域内**全部**匹配快照 | 与「按时间段清理」用户心智一致 |
| 恢复语义 | 每个应用仅恢复**一个**快照（按策略选取） | 恢复是「回到某个版本」，不是批量回滚全部历史 |
| 数据源 | 内存过滤 `groupList`，不额外扫盘 | 与现有 `loadGroups()` 链路一致，实现成本低 |
