# r06 io-tar 修改方案

五条都改 `io-tar/src/main/jni/jni.cpp` 的 `runTar`。按下面的顺序一次改完，避免各条互相拆开后又把描述符或截断问题留在中间态。

父进程在 `fork` 前：

1. 解析同目录下 `tar-cli` 的绝对路径。失败则返回 -1。
2. 把输入、输出、错误路径和 `argv` 编成标准 UTF-8。任一字符串非法则释放已复制的 `argv` 并返回 -1。此时尚未创建临时文件。
3. 若 `inputPath != nullptr`，在父进程 `open` 输入。失败则释放 `argv` 并返回 -1。
4. 在输出路径、错误路径各自的同一目录创建独占临时文件。任一创建失败则删除已创建的临时文件、释放 `argv` 并返回 -1。最终路径此阶段不 `open`。
5. 把输出、错误、输入（含调用方借来的 `inputFd`）用 `fcntl(F_DUPFD_CLOEXEC, 3)` 抬到大于等于 3。借来的 `inputFd` 只多出一个高位副本。抬升失败则关闭本次打开的描述符、删除临时文件并返回 -1。
6. `fork`。

子进程只做异步信号安全操作：保留现有的 `prctl(PR_SET_PDEATHSIG, SIGTERM)` 和 `getppid() == 1` 则 `_exit(127)`；`dup2` 到标准输入、标准输出、标准错误；从 3 关到资源上限；`execve` `tar-cli`。`execve` 失败则 `_exit(127)`。

父进程在 `fork` 之后关闭自己持有的临时文件描述符和高位输入副本，释放 `argv`，再 `waitpid`。归档临时文件只在子进程正常退出且退出码为 0 时 `rename` 到输出路径，否则 `unlink`。错误临时文件仅当大小大于 0 时 `rename` 到错误路径，否则 `unlink`。`rename` 失败时 `unlink` 临时文件并返回 -1。

## r06-1
- 判定：hold
- 问题类：失败返回前，输出文件和错误文件已经被 `O_TRUNC` 截成空文件。
- 不变量：归档结果不是成功退出时，调用前已存在的输出文件字节保持原样；原来没有该文件，结束后仍然没有。成功退出后，输出路径是本次归档，且由同目录 `rename` 换上。错误路径在临时文件大小为 0 时保持原字节；临时文件已有内容时，在子进程结束后再原子换上。
- 要动的符号或文件：`runTar` 里对最终输出路径和错误路径的 `open`（现为 `O_WRONLY | O_CREAT | O_TRUNC | O_CLOEXEC`）。改为对同目录临时文件 `open(O_WRONLY | O_CREAT | O_EXCL | O_CLOEXEC, 0644)`。临时名带进程号和单调后缀，靠 `O_EXCL` 避开已有文件。父进程记住两个临时路径。`fork` 失败、`waitpid` 失败、子进程非正常退出、退出码非 0、以及 `rename` 失败，都 `unlink` 归档临时文件，不改最终输出路径。错误临时文件按上面的非空条件决定 `rename` 或 `unlink`。输入路径改在创建临时文件之前由父进程打开，打开失败时两个最终路径都还没动。
- 明确不改什么：`TarJNI.callCli`、`TarJNI.callCliWithInputFd` 的参数和 JNI 符号保持原样。成功时归档内容的格式保持原样。`inputPath` 与 `inputFd` 都缺省时，仍然不重定向标准输入。不增加进程崩溃后的临时文件清扫。
- 本地验证：发现稿和所引源文件没有测试名。应新增断言：输出路径和错误路径预先写入已知字节；输入路径不存在时返回非 0，两份原字节仍在。错误临时文件无法创建时返回 -1，输出路径原字节仍在或仍然不存在。成功调用后输出路径等于本次归档内容。子进程写出错误文本时错误路径变为该文本；子进程未写错误时错误路径原字节仍在。

## r06-2
- 判定：hold
- 问题类：`fork` 之后的子进程调用 `main`，父进程停在 `waitpid`。
- 不变量：子进程从 `fork` 返回到 `execve` 之间只调用异步信号安全函数。父进程的 `atexit` 不在子进程里运行。`waitpid` 被 `EINTR` 打断时继续等。子进程正常退出时 `runTar` 返回该退出码；`waitpid` 失败或非子进程正常退出时返回 -1。
- 要动的符号或文件：`io-tar` 的原生构建额外产出可执行文件 `tar-cli`，其入口是现在的 `extern int main`。`libtar-jni.so` 去掉子进程对 `main` 的调用。`runTar` 在 `fork` 前用 `dladdr` 定位 `libtar-jni.so`，拼出同目录 `tar-cli` 的绝对路径；解析失败则在创建临时文件前返回 -1。同步把 `environ` 指针存到局部 `envp`。子进程在描述符整理之后 `execve(tarPath, argv.data(), envp)`，失败 `_exit(127)`。子进程不调用 `free`。父进程仍在 `fork` 返回后释放 `argv`。
- 明确不改什么：子进程不进入 JNI，也不调用 `main`。调用方传入的 `argv` 顺序保持原样。父进程死亡时子进程仍收 `SIGTERM`（现有 `PR_SET_PDEATHSIG` 与 `getppid() == 1` 检查留在 `execve` 之前）。
- 本地验证：发现稿和所引源文件没有测试名。应新增断言：父进程登记会写标记文件的 `atexit`，把 `tar-cli` 换成立即以码 0 退出的可执行文件，调用返回 0 且标记文件不存在。另一线程持有未注册 `pthread_atfork` 的锁并在锁内停留期间调用 `runTar`，调用能在子进程退出后返回。

## r06-3
- 判定：hold
- 问题类：`fork` 前从 `/proc/self/fd` 抄下的描述符列表会漏掉并发新开的管道写端，读端等不到 EOF。
- 不变量：`execve` 时子进程只留下已经重定向的标准输入、标准输出、标准错误。其它线程在 `fork` 前打开的描述符，凡是编号大于等于 3 的，都不进入 `tar-cli`。不调用 `close_range`。
- 要动的符号或文件：删除 `runTar` 父进程里的 `inherited`、`opendir("/proc/self/fd")` 和按该列表 `close` 的循环，连同 `opendir` 失败就返回 -1 的分支。子进程在三次 `dup2` 之后执行 `getrlimit(RLIMIT_NOFILE)`，对 `rlim_cur` 为有限值时从 3 到该上限逐个 `close`；`getrlimit` 失败或 `rlim_cur` 为 `RLIM_INFINITY` 时从 3 关到 65535。把现有「不要用 `close_range`，旧版 zygote seccomp 会让子进程因 `SIGSYS` 死掉」的说明留在这条循环旁。`exec` 不代替这条循环：其它线程打开的写端可能没有 `O_CLOEXEC`。
- 明确不改什么：不关闭子进程的 0、1、2。父进程不再用 `/proc/self/fd` 决定子进程要关的描述符。
- 本地验证：发现稿和所引源文件没有测试名。应新增断言：父线程创建管道后，在子进程已经进入 `runTar` 的前提下，由另一线程打开该管道写端再让 `fork` 发生；子进程读标准输入直到 EOF 并退出，`waitpid` 返回。写端在生产者一侧关闭后，读端得到 EOF。子进程执行 `execve` 前，编号大于等于 3 的描述符已关闭。

## r06-4
- 判定：hold
- 问题类：输出或错误描述符落在 0、1、2 上时，`dup2` 之后的 `close` 会关掉标准输出，或让标准错误指向归档文件。
- 不变量：归档只从子进程的标准输出进入输出临时文件，错误文本只从标准错误进入错误临时文件。三次 `dup2` 完成后，0、1、2 分别是输入、输出临时文件、错误临时文件。父进程不关闭调用方借来的 `inputFd`。
- 要动的符号或文件：`runTar` 子进程里无条件 `close(outFd)`、`close(errFd)` 的两行。在任何 `dup2` 到 0、1、2 之前，先把输出、错误和输入描述符抬到大于等于 3（见文首第 5 步）。子进程顺序固定为：有输入则 `dup2` 到标准输入，再 `dup2` 输出到标准输出，再 `dup2` 错误到标准错误，然后才做 r06-3 的关闭循环。源描述符大于等于 3，由该循环关闭。父进程在 `fork` 之后关闭自己创建的高位输入副本；调用方传入的 `inputFd` 原值不关闭。`open` 得到 0 或 1 时，也是先抬高再 `dup2`，标准错误文件描述符不会被「`dup2` 到标准输出」关掉。
- 明确不改什么：归档走标准输出、错误走标准错误、输入走标准输入。这条安排保持不变。
- 本地验证：发现稿和所引源文件没有测试名。应新增断言：调用前关闭本进程的 fd 1，成功调用后输出路径等于归档字节，错误路径只含错误文本。调用前同时关闭 fd 0 和 fd 1，成功调用后归档字节只在输出路径，错误文本只在错误路径，输出文件里没有错误文本。

## r06-5
- 判定：hold
- 问题类：`GetStringUTFChars` 的 modified UTF-8 被当作文件系统 UTF-8 交给 `open` 和 `argv`。
- 不变量：交给 `open` 和 `argv` 的字节是对应 Java 字符串的标准 UTF-8。U+0001 至 U+FFFF（含常用汉字）的字节与当前结果相同。字符串含 U+0000 或未配对代理项时，`runTar` 返回 -1，并且不创建、不截断输出路径和错误路径。
- 要动的符号或文件：`runTar` 内的 `copyString`。改为 `GetStringChars` 读取 UTF-16，自行编成标准 UTF-8：增补平面字符编成四字节序列。U+0000 与未配对代理项让 `copyString` 失败。`runTar` 在文首第 2 步处理该失败，先于任何临时文件和 `open`。输入路径、输出路径、错误路径、每个 `argv` 元素都走这一个函数。
- 明确不改什么：`io-tar/src/main/kotlin/tiiehenry/android/compress/zstd/TarJNI.kt` 的方法声明保持原样。不改 GNU tar 对成员名的内部处理。ASCII 与 BMP 路径的字节保持原样。
- 本地验证：发现稿和所引源文件没有测试名。应新增断言：输入路径、输出路径和某个 `argv` 成员名含 U+1F600 时，实际打开和写入归档成员名的字节是 `F0 9F 98 80`，成员能按该标准 UTF-8 名字读回。BMP 汉字路径的字节与改前一致。含 U+0000 的路径或参数使调用返回 -1，目标路径的原字节仍在。
