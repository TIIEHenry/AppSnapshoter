# ADR-002: 快照破坏性操作的安全顺序

## 背景

备份元数据写入、目录清理和删除返回失败时，部分调用方仍继续执行。恢复流程也存在预检前清数据、选择性恢复清除未选数据、删除配置后才解析目录的顺序错误。命名 FIFO 在一端打开失败时无法可靠终止另一端的阻塞等待。

## 决策

- 备份的压缩任务与必需元数据全部成功后，才执行卸载和旧版本清理。写入失败不得转换为成功状态。
- 恢复预检以存档原始清单为准，验证所选项及所需 APK；缺失的声明项不能静默忽略。预检通过前不改变当前应用数据。
- 高级恢复只替换所选目录。额外普通文件用 `source_file` 记录源类型，先解压到隔离目录，再替换指定文件，保留相邻文件。
- 删除分组时先保存原始路径，删除成功后再清除登记和配置；导入已有目录时先加载现有配置。
- 文件操作保留 root 文件对象，检查实际返回值。存档删除失败时不清理共享 APK；服务断连时使缓存失效。
- ZSTD 恢复使用匿名管道，经文件描述符传入 root TAR 进程；任一阶段失败都关闭管道并传播错误。
- 分组磁盘刷新使用 repository 的 IO 调度。日期选择器的 UTC 日期先转换成设备时区的日界，程序化同步筛选状态不打开选择器。

## 影响

恢复前增加完整性检查的 I/O 成本。普通文件恢复需要额外暂存空间。已有目录快照的元数据保持兼容；`source_file` 缺省为 `false`。

上述校验保证破坏性操作前具备可用输入，不提供整个应用数据恢复的事务回滚。解压开始后发生设备掉电或底层写入失败，仍需报告失败并由用户重试。

## 验证

回归用例覆盖声明项缺失、校验失败、元数据写入失败、删除失败、普通文件目标隔离、分组路径保存和本地日期边界。编译和测试结果记录于[开发状态](../progress/status.md)。
